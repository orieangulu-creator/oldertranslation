# 长辈中英翻译 App · 产品计划（PRD）

> 版本：v1.0　|　日期：2026-06-14　|　目标平台：HarmonyOS（鸿蒙）优先，兼容 Android
> 一句话定位：**给完全不懂英文、戴老花镜的 60+ 长辈，在夏威夷旅游时能"听懂、说出、看懂"英文的傻瓜级翻译机。**

---

## 1. 背景与目标

### 1.1 背景
家中长辈（60 岁以上，戴老花镜，几乎不懂英文）计划到夏威夷旅游。现有翻译 App（Google 翻译、有道等）功能多、按钮小、层级深、英文界面多，对长辈极不友好，经常"找不到按钮""不知道点哪里""看不清字"。

### 1.2 产品目标
- **核心目标**：让长辈在不需要他人帮助的情况下，独立完成"听 / 说 / 拍"三类翻译任务。
- **体验目标**：首页只有 3 个超大按钮，任何操作 ≤ 2 步即可出结果，全程中文 + 语音引导。
- **成功标准（北极星指标）**：长辈首次使用、无人指导下，三大功能各自的"一次成功率 ≥ 90%"。

### 1.3 非目标（本期不做）
- 不做多语种（仅中⇄英）。
- 不做账号体系、社交、收藏夹云同步等复杂功能。
- 不做实时双向同声传译（对话连续模式）——放入 v2 路线图。

---

## 2. 目标用户与画像

### 2.1 主用户画像：王阿姨，65 岁
- **身体**：戴老花镜，看近处小字吃力；手指不够灵活，容易误触；听力略有下降。
- **认知**：不懂英文（连 26 个字母都认不全）；智能手机只会用微信、打电话、拍照。
- **心理**：怕"点错把手机弄坏"，怕麻烦别人，对复杂界面有畏惧感。
- **场景**：在夏威夷，独自面对说英文的店员、英文菜单、英文路牌、机场广播。

### 2.2 次要用户：子女（远程协助者）
- 帮长辈提前装好、设置好 App；希望默认配置就能用，最好"零设置"。

### 2.3 关键用户洞察 → 设计约束
| 洞察 | 设计约束 |
|---|---|
| 看不清小字 | 正文字号 ≥ 22sp，关键结果 ≥ 36sp，可一键再放大 |
| 不懂英文 | 界面 0 英文；所有提示用中文 + 语音播报 |
| 怕点错 | 首页只放 3 个按钮；危险操作无（不设删除/设置等入口在首页） |
| 手抖误触 | 按钮大（≥ 1/3 屏宽）、间距大、点击区域大；防误触确认 |
| 不会找返回 | 每页左上角超大"⬅ 返回首页"；物理返回键也回首页 |

## 3. 核心使用场景（夏威夷实景）

1. **听**：店员对王阿姨说英文（"Your table will be ready in ten minutes."）→ 王阿姨点"听"→ 手机听到并显示大字中文"您的桌子十分钟后就好"。
2. **说**：王阿姨想问"洗手间在哪里？"→ 点"说"→ 对手机说中文 → 手机显示并大声播报英文"Where is the restroom?"，把屏幕给店员看。
3. **拍**：面对全英文菜单 → 点"拍"→ 拍照 → 手机框出英文并显示对应大字中文译文。

## 4. 信息架构与首页设计

### 4.1 信息架构（极简两层）
```
首页（3 个大按钮）
├── 听  → 听译页（英文语音 → 中文）
├── 说  → 说译页（中文语音 → 英文，语音+文字）
└── 拍  → 拍译页（拍照 → OCR → 中文）
（无三级页面；设置藏在首页一个不显眼的小角标，仅供子女使用）
```

### 4.2 首页视觉规格
- 竖向排列 3 张大卡片，每张占屏高约 1/3。
- 每张卡片：**超大图标 + 中文大字标题 + 一句话说明**。
  - 🟢 **听**　大耳朵图标　"听别人说英文"
  - 🔵 **说**　大嘴巴图标　"我说中文给老外看"
  - 🟠 **拍**　大相机图标　"拍英文给我看懂"
- 配色高对比（白底 + 高饱和大色块），色弱友好；图标 + 文字双重表意。
- 进入首页自动语音播报一次："请选择，听、说、还是拍。"

## 5. 功能规格

> 通用交互原则：**一个主操作大按钮 + 大字结果 + 自动语音播报 + 一键重来 + 返回首页**。

### 5.1 功能一：听（英文语音 → 中文）
**目的**：听懂对方说的英文。

**流程**：
1. 进入页面 → 顶部大字提示"请把手机靠近对方，点下面的大圆钮开始听"。
2. 点中央超大"🎤 开始听"圆钮 → 钮变红 + 显示声波动画 + 文案"正在听…"。
3. 实时把英文转写成文字（小字，灰色，供参考）。
4. 说话停止（静音检测）或用户点"停止" → 立刻显示**超大中文译文**，并自动**朗读中文**。
5. 底部两个大按钮：**🔁 再听一句**　|　**⬅ 返回首页**。

**规格要点**：
- 自动静音断句（停顿约 1.5s 视为说完），无需精确手动停止。
- 中文结果字号 ≥ 36sp，可点"放大"再放大到 ≥ 48sp。
- 识别失败/没听清 → 大字"没听清，请再说一次"+ 语音提示，绝不报英文错误码。

### 5.2 功能二：说（中文语音 → 英文，语音 + 文字）
**目的**：把长辈想说的中文，变成英文给老外看 + 念给老外听。

**流程**：
1. 进入页面 → 大字提示"点下面的钮，对我说中文"。
2. 点"🎤 我要说"→ 长辈说中文 → 转写中文（确认对了）。
3. 自动翻译 → **大字英文** + 上方小字中文原话对照。
4. **自动大声朗读英文**（给老外听），同时屏幕英文放超大，**可一键"全屏给对方看"**（横向超大英文，亮度拉满）。
5. 底部：**🔊 再读一遍**　|　**🔁 重新说**　|　**⬅ 返回首页**。

**规格要点**：
- 提供常用语快捷卡（可选）：洗手间在哪？/ 多少钱？/ 我要这个 / 谢谢 / 帮我叫救护车。一点即出英文+朗读，应急更快。
- "全屏给对方看"模式：黑底白字超大英文，方便嘈杂环境给店员看。
- 朗读英文用清晰自然的英文 TTS，语速可调（默认偏慢）。

### 5.3 功能三：拍（拍照 → OCR → 中文）
**目的**：看懂菜单、路牌、说明书等英文。

**流程**：
1. 进入页面 → 相机取景 + 大字提示"对准英文，点下面大钮拍照"。
2. 点超大快门 → 拍照 → 自动识别图中英文。
3. 显示两种结果，默认"整段中文"模式：
   - **整段译文模式**：直接给一大段中文译文（默认，最易懂）。
   - **对照模式**（可切换）：在原图上把英文区域旁标中文（适合菜单逐项看）。
4. 长段译文支持"朗读全文"。
5. 底部：**📷 重拍**　|　**🔆 放大看**　|　**⬅ 返回首页**。

**规格要点**：
- 拍照支持从相册选已有照片（子女可提前拍好）。
- 自动提示对焦/光线不足："太暗了，请开灯或换个角度"。
- 识别不到英文 → 大字"没找到英文，请对准文字重拍"。

## 6. 无障碍与适老化设计规范（贯穿全局）

| 维度 | 规范 |
|---|---|
| 字号 | 正文 ≥ 22sp；按钮文字 ≥ 26sp；结果 ≥ 36sp；支持系统超大字体 |
| 触控 | 按钮最小点击区 ≥ 64dp×64dp；元素间距 ≥ 16dp；首页按钮 ≥ 1/3 屏 |
| 对比度 | 文字/背景对比度 ≥ 7:1（WCAG AAA）；不靠颜色单独表意 |
| 语音 | 每个页面进入有中文语音引导；结果自动朗读；可关 |
| 反馈 | 点击有震动 + 音效 + 视觉变化三重反馈 |
| 容错 | 所有错误用中文人话 + 语音，给出"下一步怎么办"，绝不出现英文/错误码 |
| 导航 | 全局"返回首页"超大按钮固定左上；最多两层；无隐藏手势 |
| 网络 | 无网/弱网时给大字提示"请连接网络后再试"，并提示连 Wi-Fi 步骤 |
| 默认值 | 出厂即最优配置，长辈无需任何设置即可用 |

## 7. 技术架构

### 7.1 平台与框架
- **主平台：HarmonyOS（鸿蒙）**，采用 **ArkTS + ArkUI（Stage 模型）** 原生开发，调用鸿蒙系统的相机、麦克风、TTS 能力。
- **兼容策略**：UI 与业务逻辑分层，核心"翻译/语音/OCR 服务层"以接口抽象，便于后续移植到 Android（Kotlin + Jetpack）。
- 选择鸿蒙原因：目标长辈很可能使用华为/鸿蒙手机；原生框架对适老化（大字、无障碍）与设备能力支持最佳。

### 7.2 分层架构
```
┌─────────────────────────────────────────┐
│  表现层 UI（ArkUI）首页 / 听 / 说 / 拍      │
├─────────────────────────────────────────┤
│  交互编排层（页面状态机、语音引导、容错）     │
├─────────────────────────────────────────┤
│  能力服务层（接口抽象，可替换实现）           │
│   ├─ ASR 语音识别（中/英）                 │
│   ├─ TTS 语音合成（中/英）                 │
│   ├─ Translate 文本翻译（中⇄英）           │
│   └─ OCR 图片文字识别（英）                │
├─────────────────────────────────────────┤
│  云端 API 适配层（HTTP/SDK + 重试/超时）     │
└─────────────────────────────────────────┘
```

### 7.3 翻译/语音/OCR 引擎选型（纯云端方案）

按用户决策采用**纯云端 API**。推荐主选 + 备选，便于按可用性/成本切换：

| 能力 | 主选 | 备选 | 选型理由 |
|---|---|---|---|
| 文本翻译 中⇄英 | **微软 Azure Translator** | DeepL / 腾讯 / 有道 | 单厂商可同时覆盖翻译+语音；中英质量稳定；全球节点（夏威夷可用） |
| 英文 ASR（听） | **Azure Speech (ASR)** | Google Cloud Speech / 讯飞 | 英文识别强、支持实时流式与静音断句 |
| 中文 ASR（说） | **讯飞 ASR** 或 Azure Speech | 百度 | 中文（含口音/方言倾向）识别更自然 |
| TTS 中/英 | **Azure Neural TTS** | 讯飞 TTS | 神经网络发音自然、可调语速，老人听得清 |
| OCR 英文（拍） | **Azure Vision OCR** | 百度 OCR / 华为 ML Kit 云侧 | 印刷体英文识别准、返回坐标便于"对照模式"标注 |

> 建议：**优先选用同一云厂商（Azure）打通翻译+语音+OCR**，降低集成与运维复杂度；中文语音如追求自然度可单独接讯飞。所有 Key 走服务端代理（见 7.4），不硬编码进客户端。

### 7.4 网络与安全
- **API 密钥不放客户端**：客户端 →（HTTPS）→ 自建轻量后端网关 → 云厂商。网关负责密钥保管、配额限流、错误归一化。
- 统一超时（如 ASR 流式 10s、翻译 5s、OCR 8s）+ 指数退避重试；失败归一为中文友好提示。
- 弱网降级：压缩音频、降低采样率重试；连续失败提示"网络不好，请换个地方再试"。

### 7.5 隐私
- 语音、照片仅用于本次翻译，**默认不留存**；不上传通讯录/位置等无关数据。
- 隐私政策用大字中文 + 语音讲解；首启一次性极简授权（麦克风、相机、网络）。

### 7.6 非功能需求
- **性能**：听/说出结果 ≤ 2s（正常网络）；拍照出结果 ≤ 3s。
- **稳定**：崩溃率 < 0.1%；弱网下不卡死、必有反馈。
- **续航/流量**：单次翻译流量尽量小；显示"本次约用 X KB"（可选）。

## 8. 测试策略（含两个测试子 Agent）

为保证"流程可用"与"翻译准确"，配置两个自动化测试子 Agent（定义见 `.claude/agents/`）：

1. **对话模拟测试 Agent（dialogue-tester）**
   - 角色：扮演夏威夷各种真实场景（餐厅、机场、商店、问路、就医、酒店），针对"听/说/拍"生成测试对话与用例，逐步走查交互流程，记录每步是否"长辈可独立完成"，输出可用性测试报告与翻译测试语料。
2. **翻译校对 Agent（translation-proofreader）**
   - 角色：精通中英双语与适老化表达，对上一个 Agent 产出的所有中⇄英译文逐条校对，给出准确性评分、错误类型、是否"老人能听懂的中文/老外能看懂的英文"，输出校对报告与修正建议。

两 Agent 形成"生成用例 → 校对质量"的闭环。测试产物见 `tests/`。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 夏威夷网络/流量受限（用户选纯云端） | 无网时三功能不可用 | 大字提示连 Wi-Fi；v2 增离线兜底包；建议子女备好境外流量卡 |
| 嘈杂环境英文识别差 | "听"不准 | 引导靠近对方；显示英文原文供核对；可重听 |
| 中文方言/口音识别差 | "说"不准 | 转写后让用户确认；提供常用语快捷卡兜底 |
| 老人仍觉得复杂 | 用不起来 | 持续做真人测试；语音引导 + 极简 3 按钮 |
| 翻译出错引起误会（如就医） | 严重场景风险 | 校对 Agent 重点覆盖应急/医疗用语；关键句人工校准词库 |
